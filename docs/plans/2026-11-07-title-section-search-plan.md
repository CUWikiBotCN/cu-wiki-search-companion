# 标题搜索可选纳入小节：实施计划与验收

本计划的实现与本地验证已完成，纳入 0.4.0；尚未进行新版本安装验收。下文保留已接受的设计契约；具体检查结果及浏览器覆盖边界见[验收记录](../acceptance/2026-11-07-section-search.md)。

2026-11-07 审阅补充：撤下 `Alt+Shift+S`；增加页面限定的小节查询，覆盖“地形扫描仪 → 你知道吗”及大量物品同名小节的精确定位。进一步按用户反馈支持 `地形 #你知` 双侧片段筛选，并以 ASCII `#` 显式触发小节搜索，无需先选定完整页面名。下述交互已纳入本地实现。

## 1. 目标与范围

用户在“页面标题”模式勾选“包含小节”，输入“生血晶等七种晶体”，找到“世界生成”中的对应小节，并能复制目标、打开小节或插入 `[[世界生成#生血晶等七种晶体|生血晶等七种晶体]]`。

已完成的引用提取修复作为基线：`19ae80e`。该修复与本功能分别交付。本计划不重新修改它的正文提取语义。

### 已明确的要求

- 入口采用标题模式中的复选框，默认不勾选，支持快捷键切换。
- 小节搜索由运行态组织，不将小节伪装为普通页面塞入 `TitleIndex`。
- 用户需要准确限定所属页面，例如搜索“地形扫描仪”的“你知道吗”，不能被其他页面的同名小节淹没。
- 为后续“正文命中定位所属小节”保留结构接口，但本批不实现该功能。
- 按已接受计划实现并验证；提交、推送、安装与 Wiki 编辑分别处理。

### 建议首版采用的取舍

| 项目 | 建议 |
| --- | --- |
| 勾选状态 | 手动选择每次页面加载关闭，页面内保留；`#` 临时启用不改写手动选择，删除后恢复；不写 GM preference |
| 小节来源 | 只读已有且修订匹配的 wikitext 源码，首次勾选不自动下载正文 |
| 缺失源码 | 建议对明确单页意图自动补齐；片段/全站查询仍明确获取，显示覆盖情况；自动获取边界已接受 |
| 结果 | 页面、小节分组；页面组在前，组内结果与原排序完全相同；两组各最多 20 条，不互相占额度 |
| 匹配 | 支持全站小节名称搜索，以及 `页面片段#小节片段` 的组合筛选和选定页面后的单页搜索；名称支持精确、前缀、连续子串匹配，不新增分词或模糊检索依赖 |
| 小节缓存 | 按需创建的内存派生结构，不新增数据库表或持久化快照 |
| 不确定链接 | 明示“链接待核对”；用户单独核对后再执行复制目标、打开小节、插入；失败时仍可打开所属页面 |
| 快捷键 | 采用面板内 `Ctrl+Alt+S`；Chrome/Firefox 的现场可达性和隔离交互检查通过，登录编辑器覆盖边界见验收记录；保留 Tab 和 Space |

“页面组在前”保证已有标题搜索的熟悉顺序，但小节精确匹配可能位于页面组之后。首版保持分组标题和显示条数可见，允许点击“小节”分组入口滚动到该组；不另做跨域打分。此取舍可在审阅时调整。

### 本批不包括

- 全文按小节检索、正文摘要归属及文本坐标映射。
- 全站预先调用解析 API，或展开所有模板来发现动态小节。
- 任意 HTML ID/锚点的全站搜索；通用模板执行器或完整 MediaWiki 解析器。
- 保证小节在任意未来修订中拥有不变身份；首版只保证已知版本下不误绑定。
- 新的同步调度体系、独立下载队列、Worker 或小节快照格式。

## 2. 使用流程

### 2.1 开启与准备

1. 标题模式展示原生复选框“包含小节”；其他模式隐藏它，隐藏时快捷键不生效。直接切换键仍是本批要求，不能用 Tab/Space 支持冒充已经完成该快捷键。
2. 勾选后保持页面结果可用，异步从已缓存源码准备小节结果。
3. 页面内只维护一份小节内存结构；连续切换不重复初始化，晚到的准备结果不能在取消勾选后重新显示小节。
4. 输入法组合期间不执行快捷键，不消费编辑器/浏览器中不属于本功能的按键；忽略长按重复事件。复选框本身支持 Tab 和 Space。
5. 快捷键与鼠标调用同一个状态变更动作，均触发重新检索。搜索条件判等加入 `includeSections`、页面限定模式、绑定的 page ID 及小节查询，不能沿用旧条件误保留选择。

### 2.2 页面限定与同名小节

提供两条入口，直接输入不要求先选定页面：

- **直接输入片段**：`地形 #你知`。左侧匹配页面名，右侧匹配小节名称，两个条件必须同时满足；可以返回 `地形扫描仪 › 你知道吗`，也可以返回其他符合两个条件的页面小节。不要求输入完整名称、不要求先从候选中选定一个页面。
- **从页面结果进入**：先搜索“地形”，点击某个页面行的“查看小节”按钮（支持 Tab 到达、Enter 激活）。将输入改为规范页面名加 `#`，绑定所选 page ID，由 `#` 临时启用小节，并将焦点放到分隔符之后。这是可选的精确单页入口。

在原始输入上按第一个 ASCII `#` 分隔，再分别去除左右首尾空白并归一匹配；右侧后续 `#` 属于小节查询。不得先做 NFKC 再分隔，以免将合法的全角 `＃` 页面名字符当成查询语法。默认不按空格猜拆页面与小节名称，保留字段内部空格的既有匹配规则。

| 输入 | 查询行为 |
| --- | --- |
| `地形 #你知` | 页面名匹配“地形”，且小节名匹配“你知” |
| `地形#` | 列出名称匹配“地形”的页面的小节，提示继续输入来缩小范围 |
| `#你知` | 在当前命名空间的可用页面中搜索名称匹配“你知”的小节 |
| `#` | 进入小节搜索并显示输入提示，不枚举全站小节 |

直接输入显示“页面筛选：地形”；只有通过页面结果明确绑定 page ID 后才显示“仅此页：地形扫描仪”。片段匹配不会因存在精确页面名而排除其他包含该片段的页面，精确匹配只参与排序。编辑左侧即清除绑定、恢复片段筛选；命名空间变化需重新校验绑定，越界则清除。输入右侧不清除绑定。首版不将重定向源视为有正文小节的页面，必要时提示选择目标页面。

`#` 查询只展示小节结果，每行清楚展示完整所属页面、完整小节名与上级路径；不再混入页面结果。检索应对符合页面条件的所有可用小节应用右侧条件，最后排序和截断为 20 条。不能取已有 `TitleIndex.search(..., 20)` 的页面候选再查小节，也不能先取全站前 20 个小节再过滤；否则目标即使满足两个条件也可能被提前丢弃。页内重复小节仍按路径/出现次序区分。

范围状态分成手动选择与查询语法两部分：`manualIncludeSections` 仅由鼠标/快捷键改变，页面加载默认 false；`syntaxRequiresSections` 从标题模式当前输入是否包含 ASCII `#` 派生。实际范围为两者的逻辑或，不用保存进入语法前的快照，也不将输入 # 写成手动偏好。删除 # 或清空输入后自然恢复当前手动选择；手动原本关闭则仅搜页面，手动原本开启则恢复页面/小节分组搜索。普通编辑查询不改变手动状态。

复选框显示实际生效状态，仅由语法开启时紧邻标注“由 # 临时启用”，并提供可访问说明。鼠标/快捷键主动关闭时，统一将手动选择置 false、退出 # 查询并保留左侧页面片段，左侧为空则清空；不能留下 # 又暗中忽略其含义。无 # 时主动开启仅设置手动选择。切换其他模式不解释 #，回到标题模式重新派生范围。输入法组合期间不切换，组合结束后再解释。搜索条件使用实际范围及完整解析条件，不能只看手动开关而漏掉语法变化。

输入 # 本身不触发批量下载或链接核对；仅第 2.3 节约定的明确单页意图可以自动补齐源码。

示例路径：打开面板 → 输入 `地形 #你知` → 选择 `地形扫描仪 › 你知道吗` → 如有必要先核对链接 → Shift+Enter 插入 `[[地形扫描仪#你知道吗|你知道吗]]`。最终目标取候选页面的规范名称与真实锚点，显示文字取完整小节名，不能把用户输入的片段拼成链接。其他页面只有同时满足左侧筛选才会参与查询。

### 2.3 覆盖与下载

覆盖提示以当前命名空间下的活动、非重定向 wikitext 页面为分母：

- `N`：本地标题元数据已知的合格页面数；标题基线未完成时显示“已知 N 页”，不称全站完整。
- `M`：有字符串源码、存在有效修订号，且 `contentRevisionId === revisionId` 的页面数；空源码也是已覆盖。
- 另列缺失/待更新页数，以及含不支持结构或待核对锚点的页数。`M/N` 只表示源码覆盖，不表示模板生成小节全部可检索。
- 未勾选时不为这些统计全表物化正文；首次准备后在增量刷新中维护统计，不在每次按键时重算。

提示示例：“已覆盖 80/100 个已知页面，20 页正文待下载或更新”。覆盖不完整时，空结果文案应提示可能受缓存范围影响。

“下载/更新正文源码”是明确的网络动作，使用已有非 CSS 正文同步范围。这个范围还包括 BSON/Lua 页面；按钮说明需写清它更新共享正文缓存，不承诺只下载 wikitext 或只下载当前 namespace。选择这一方案是为了复用现有任务、重试、限额和写锁，不新建下载协议。下述页面限定入口另支持明确的单页任务选择。

不能直接调用当前 `synchronizeContent()` 就认为满足要求：它根据已加载的索引选择 content/CSS 会话，存在只加载 CSS 时跳过普通正文的路径。应新增明确的普通正文同步入口，复用既有 `contentSyncSession`，无论 CSS 是否已加载都请求普通正文；不顺带初始化正文/Lua索引或启动 CSS 下载。已有正文/Lua索引若已加载，继续按现有机制追平。

片段查询的覆盖提示须说明匹配页面中哪些源码缺失；缺失源码的页面不能伪造小节候选，也不能报告为确定没有目标小节。可展开缺失页面列表并选择单页获取，不自动批量下载所有匹配页面。

**已接受：明确单页意图时自动补齐。** 这使“查看小节”成为一次完整操作，不需要用户再点一次获取：

- 点击某页的“查看小节”，绑定真实 page ID；该页源码缺失或相对本地标题元数据已过期时，自动请求该页。
- 在标题模式输入 #，左侧在当前命名空间唯一精确对应一个完整、规范页面名时，输入结束并稳定 500 ms 后可自动请求该页。名称身份按页面名规则判定，不用搜索的繁简转换/紧凑子串归一值判断唯一性；标题基线未就绪或有歧义时不自动请求。500 ms 是初始防抖值，非性能承诺。
- 只有片段匹配，即使当前恰好仅有一个候选，也不据此自动请求；`#你知`、裸 #、普通勾选、结果行悬停或键盘经过同样不触发。
- 可用源码直接复用；没有小节命中、零小节或复杂结构不等于缓存过期，不能据此反复联网。自动请求仅补齐相对已知修订的缺失，不承诺实时探测远端全部修改。

自动获取显示“正在获取《页面名》的小节”，失败保留缓存结果并提供手动重试，不把失败伪装为空结果。一个面板会话内按 page ID + 已知修订记录自动尝试；持续修改右侧关键词、反复开关或失败重绘不重新触发。该记录是有界的：初始上限 64 个自动目标，达到后本会话改用明确获取按钮，不驱逐旧失败记录后重复自动请求。已有 API 的有限重试继续适用，不另建自动重试循环。

实现复用原正文任务、批量提交、修订校验及写锁路径，增加明确 page ID 集合的选择能力；请求前重新检查页面身份/资格，只选择所需页面的任务，不将其他页面待办误标完成或删除。单页请求与全站请求同时到达时，只有已覆盖该 page ID 的会话才能共用 Promise；否则顺序补做，避免现有无参数会话合并吞掉不同目标。重复同页请求合并。自动任务等待期间仅保留最新仍有效的单页意图，取得写锁后再次校验，不能将连续输入变成积压下载队列；明确点击的手动下载另按原任务语义处理。

清除 #、切换目标/模式或关闭面板时撤销未发出的自动意图。已发出的共享请求可完成缓存写入，不强行中断其他消费者的任务；晚到结果只能按当前查询重新筛选，不能恢复旧搜索、抢焦点或执行插入。UI 分别说明全站下载与单页获取的范围。缺锁、断网、超时和部分失败保留可用本地结果。后台每批已提交事实通过现有刷新/广播路径增量补充小节。退出小节搜索不取消已经明确启动的共享下载，也不再发起新自动获取。

自动补齐源码不等于自动核对复杂锚点，本批仍保留独立“核对链接”动作及核对后再操作的边界。

### 2.4 结果及操作

小节行展示小节名称、所属页面、上级标题路径；同名小节附出现次序。所有文本通过文本节点渲染，不将解析 API 的 HTML 字符串传给 `innerHTML`。

| 动作 | 页面结果 | 链接已就绪的小节结果 |
| --- | --- | --- |
| 点击主体 / Enter | 保持复制纯页面标题 | 复制 `页面#原始锚点` |
| 打开 / Ctrl 或 Cmd+Enter | 打开页面 | 打开小节 |
| 复制插入内容 | 保持现有逻辑 | 复制 `[[页面#锚点|小节显示标题]]` |
| 插入 / Shift+Enter | 保持现有逻辑 | 在编辑器当前选择处插入上述链接 |

小节显示文本来自完整小节名称，不使用用户输入的片段。File/Category 命名空间链接继续保留前导冒号，防止嵌入文件或添加分类。标题/锚点中的语法特殊字符必须经过对应目标/显示文本转义；不复用 URL 百分号编码替代 wikitext 转义。

未就绪的小节显示“核对链接”和“打开所属页面”；生成小节目标的动作不可执行，并有可访问说明。普通 Enter 不隐式变成联网核对，核对成功也不自动复制/打开/插入。这样核对期间用户移动编辑器光标，不会触发晚到的插入。

分组标题不是结果行；方向键在实际可操作结果行间移动。待核对行仍可获得焦点和选择，其核对按钮可通过 Tab 到达。后台补充结果尽量保留同一结果的焦点；旧结果失效时按现有规则回到搜索框，不把选择转给同页另一个小节。

## 3. 小节识别与锚点契约

### 3.1 纯解析接口

新增 `parseSections(source)`，返回小节列表、层级关系、源码范围及无法可靠解析的原因。建议字段：

```ts
interface ParsedSection {
  localId: string;             // 当前源码版本内的身份
  level: number;
  parentId?: string;
  displayTitle: string;
  headingStart: number;
  headingEnd: number;
  directBodyEnd: number;       // 下一个标题起点；不重复包含后代正文
  subtreeEnd: number;          // 下一个同级/更高层标题起点
  anchorCandidate?: string;
  needsResolution: boolean;
}
```

偏移统一约定为原始 JS 字符串的 UTF-16 索引，CRLF 按原样计数，不用清洗后字符串的位置冒充源码位置。这些范围描述原始源码，本批不创建 `{纯文本位置 → 小节}` 表。

初始支持直接出现在页面源码中的 1–6 级等号标题，识别层级跳跃、重复标题、空行和 CRLF。标题中的普通文本、链接显示文字、粗斜体及已验证实体可清洗为显示标题；清洗标题链接时只保留显示内容，不照搬正文提取器同时保留链接目标和标签的逻辑。

先识别注释、引用、nowiki、pre、syntaxhighlight/source 及已知不可产生标题的标签区间；标题扫描跳过这些范围。用位置保留的扫描/遮罩，避免删除文本后改变偏移或拼出新的行首。共享的是已明确的词法规则，不是“所有调用者统一删除同样内容”。不改变当前全文对代码或 nowiki 内容的既有行为。

HTML 标题、跨行/复杂标题、未展开模板/解析函数等首版不靠一条正则宣称完整支持；应记录解析不确定性。模板直接生成而源码不存在标题标记的小节，不保证被全站搜索发现。识别 `<span id>` 或模板参数不自动创建小节记录。

### 3.2 链接可信度

区分显示标题、搜索归一值、原始锚点和编码后的 URL。搜索的繁简转换/小写化不得改写锚点。

- **本地可确定**：实现前已用站点解析结果验证的普通直接标题，且该页面参与小节生成和锚点分配的结构完整可识别、无歧义。重复标题需要按同页完整锚点集合处理碰撞，不能只对相同显示标题计数。
- **待核对**：未展开模板/解析函数可能影响标题集合、HTML 标题/自定义 ID 冲突、复杂格式或无法唯一映射的情况。即使目标标题本身简单，也不能忽略同页其他不确定结构。本轮不建立未经核验的“模板一定不会生成标题”白名单。
- **已核对**：用户显式请求单页章节元数据，响应与当前页面/正文版本一致，且目标映射唯一。

本地计算是有限支持范围内的能力，不承诺复现全部 MediaWiki 渲染规则。实际页面常使用模板，因此部分常用页面第一次使用小节链接需要一次“核对链接”。离线时仍能搜索本地标题，未核对的复杂目标不生成可能错误的链接；这属于首版明确限制。

核对复用 `WikiApi` 的超时、错误和重试机制，只读请求单页 `action=parse` 的章节信息，不取整页 HTML，不写 Wiki。实施前验证灰机版本支持的参数、锚点字段和偏移单位；不得假定最新 `tocdata` 已在该站部署。

响应必须校验页面身份和修订，并与请求开始时的数据令牌匹配。优先按明确源码位置/结构关联，不以“第一个同名标题”猜测对应关系。API 的 section edit index 不能当长期身份；若字段给的是 byte/codepoint 偏移，先转换为约定坐标。无法唯一映射时保持待核对并解释原因。

同一页面/正文修订/当前解析规则的请求合并，首版只在内存缓存核对结果（建议最多 64 页、5 分钟有效期）；过期、页面刷新或已知内容变更后重新核对。不声称页面修订号能完整覆盖模板依赖变化或外部未来编辑。迟到响应在源版本改变、索引重建或运行态销毁后不能安装；普通换查询可缓存响应，但不能改变新查询的选择或触发动作。

读取的原始锚点交给现有 URL 构造函数编码一次；若接口只提供已编码值，适配层明确转换/传递契约。避免将已编码片段再次送入 `escapeIdForLink`。

### 3.3 本地身份与更新

运行态记录绑定 `pageId + contentRevisionId + localSeq + localId`，用于区分同页多个小节及丢弃旧响应。锚点是链接目标，不被当成跨修订不变的身份。

同一修订的后台刷新保留结果键；修订变化时首版保守失效旧小节选择，不将旧 `_2` 的焦点迁到新 `_2`。未变化的其他页面结果继续保留选择。API 核对改变锚点时保持原本地行身份，以免正在核对的行突然丢失焦点。

| `README.md`、`ARCHITECTURE.md` | 显式纳入小节的规则、快捷键、复制语义、数据覆盖和离线限制 |

不新增顶层搜索模式。`PageSearchRuntime` 可有独立小节准备状态，但 UI 仍在 title 模式请求可选的小节结果；不让 main.ts 持有索引。

小节索引按 CSS 的模式参考实现：在只读事务中捕获页面变化和 localSeq，事务结束后分批解析并协作式让步；成功安装状态后才推进已应用序列。删除、重定向、内容模型变化、源码变旧均移除原小节。失败不标记已追平；强制重建使用安装代次防止旧异步任务覆盖新状态。未初始化时只记待刷新，不因后台通知主动扫描正文。

只纳入有效修订匹配的 wikitext 页面；BSON/Lua/CSS 不创建小节。标题索引继续只读取轻量标题头。关闭复选框停止小节查询/显示，允许复用已准备内存；未勾选过的标签不创建小节索引。

小节匹配可复用 bootstrap analyzer 的归一能力，不调用 `queryTokens` 或加载新的 jieba。现有标题模式自身加载 jieba 的行为保持不变。普通全站小节查询按精确、前缀、包含分层；组合查询先应用页面和小节两个条件，再按页面匹配层级、小节匹配层级、页面标题、page ID、源码位置稳定排序，不与原标题索引原始分数比较。页面条件每页计算一次，复用轻量标题元数据和预先归一的名称，不复制完整正文。空字段仅在第 2.2 节定义的目录/全站查询中作为无约束；非空字段归一后为空时返回空结果，不能意外放宽成全站匹配。

本批不变更数据库 schema、页面事实格式、现有 title/content/lua 快照 payload 或正文 extractor 版本。不为避免改版本而偷偷改变正文提取语义；如实现发现必须改变，则先报告并重新界定本批范围。

| U3 链接目标与核对 | 原始锚点契约、单页核对/合并/失效、页面/小节复制打开插入 | 特殊字符、命名空间、版本不匹配、晚到响应、离线失败测试通过；核对不自动插入 |
| U4 面板整合与验收 | 复选框、快捷键、全站/页面限定查询、分组、焦点和状态；更新文档 | 完整检查及隔离浏览器验证，通过下列验收清单 |

建议按三个交付节点推进：

1. **先完成 U0**：用目标站点少量只读样例核对章节响应与锚点，确认快捷键；将查询语法、开关转换、单页获取触发条件整理成固定验收表。交付支持矩阵与仍存在的限制。
2. **完成 U1–U3**：先确定小节记录/目标契约，再实现解析匹配、增量生命周期与单页同步、链接核对。使用固定夹具验证，不把联机请求放进纯查询函数。交付可审阅差异与定向测试结果。
3. **完成 U4**：面板接线并验证完整编辑流程，跑项目完整检查和 Firefox/Chromium 浏览器验收。重点演示“地形 #你知 → 候选 → 插入”、删除 # 恢复范围、冷缓存自动获取与失败重试。交付实际通过项、未覆盖项及发布候选。

U0 确认的契约若与已接受行为相容，后续实现无需重新讨论相同产品取舍；若必须缩减功能或改变网络范围，再明确报告差异。提交、推送、真实脚本安装与上述实现节点分别记录，不用旧授权推定本轮发布权限。

U0 只处理少量请求，不抓取全站渲染内容、不保存 Wiki 编辑。真实脚本安装与发布另行处理；组件夹具通过不等于已安装整包验收。

## 7. 后续正文定位的接入点

本批保留的层级和原始源码范围供下一批复用，但它们不能直接映射现有摘要偏移。未来应在正文提取阶段把可搜索文本块关联到 `localId`，并在归一化/摘要生成中保留归属：

1. 导言无小节，定位页面；正文块归最近且最深的有效小节。
2. 父级路径用于展示，不重复索引所有后代正文。
3. 同页多处命中可返回多个小节；查询词跨小节分散时保留页面级匹配，不捏造单一命中小节。
4. 用明确的坐标契约处理 NFKC、繁简转换及空白压缩，不能从截断后的 snippet 反推位置。
5. 只有到这一批实际变更正文派生格式时，才更新对应提取器/索引兼容版本及恢复测试。
