# 搜索局部优化测量记录（2026-11-06）

本轮完成正文摘要文本复用、Lua 全量重建筛选和单次查询分词复用。合成语料下，长文热查询及混合页面的 Lua 重建均在三轮测量中改善；结果逐字段一致。快照恢复、短文和全 Lua 对照未触发本轮回退门槛。短查询主要确认减少分词工作，不承诺可感知的固定延迟降幅。

## 源码与方法

- 基线：`0a29eca` 的归档源码；`e50e7c7` 仅整理原有公开文档，没有生产代码差异。
- 候选：0.3.11 工作区中的三类索引改动，没有升版。基线、候选源码 SHA-256、测量工具身份及浏览器 bundle SHA-256 见[原始采样数据](2026-11-06-local-search.json)。归档没有自己的 Git 元数据，不能用其父仓库的 HEAD 冒充基线身份。
- Node 24.18.0；依赖沿用锁定安装。当前 npm 12.2.0，packageManager 声明 12.1.0；本轮没有重新安装依赖或更改锁文件。
- Node 使用真实 Jieba；浏览器使用 bootstrap 分词器，Chrome 156.0.8078.79 无头会话。两个环境分别比较，不互相代替。
- 每个环境使用相同驱动、语料和查询，分别采基线三轮与候选三轮，每轮热身 5 次、热采样 30 次。基线轮次与候选轮次分别执行，并非逐样本交错；测量期间不同时运行测试、构建或另一组计时。
- 冷查每例每轮只有一个观测。恢复、恢复加首查、Lua 重建均为每个样本新建索引；构造发生在计时前，恢复及实际重建在计时内。计数插桩、哈希和结果比对不进入计时。
- 为排查短查询计时噪声，另做 54 组相邻基线/候选对比：三轮、每轮 5 次热身和 30 个样本，偶数轮反转运行顺序，覆盖两种分词器和三个索引。

下表取三个轮次 p50 的中位数，单位 ms。每轮 p50/p95、冷查、所有原始样本、调用计数和结果哈希都在 JSON 中；完整结果对象留在私有验证证据中，已实际逐字段比对。

## 正文方案调整

[原计划](../plans/2026-11-06-2121-perf-search-local-optimizations-plan.md)将空白整理放到快照导入阶段。首次实现虽降低热查询成本，却把 Node 快照恢复从约 0.4 ms 增至 11.9 ms，三轮都超过“20% 且 1 ms”的回退门槛，未予保留。

2026-11-06 经用户确认，改为按需整理：

1. 新建及更新的正文直接复用现有提取器已整理的文本。
2. 快照导入只记录待整理页面 ID，不扫描全文。
3. 最终返回的页面首次命中时整理文本，原位写回现有 Map 并清除 ID 标记；后续查询复用。更新和删除同样清除标记。

这取代原计划中“快照导入时整理”和“快照冷查也零整理”的验收口径。快照首次命中允许一次整理，热查必须为零；恢复及恢复加首查仍受原回退门槛约束。没有新增全文缓存、持久化字段或兼容键。未命中的旧快照文本保留原样，输入正文条目不被修改。

正文语料为 20 篇约 11.2 万字符的长文和 20 篇短文，每次返回 20 项。

| 大小写不敏感热查 | 13.364 | 0.636 | 8.3 | 0.6 |
| 繁简归一化 fallback 热查 | 12.618 | 1.473 | 10.8 | 3.8 |

分词复用仍保留 AND→OR、标题短 CJK 限制、模糊匹配、过滤和排序。bootstrap 的多词查询可能因整句 token 进入 OR，因此测量中的 `and` 标签表示首先尝试 AND，不代表所有分词器都没有回退。相邻交错复核中，18 类短查询的三轮 p50 中位数均低于基线；耗时通常只有零点几毫秒，不将该结果外推成固定百分比提速。

## 复跑与边界

使用同一份当前测量工具，分别将 `baseline_root` 指向上述基线源码、`candidate_root` 指向候选源码，两个目录使用锁定依赖：

```bash
mkdir -p .local/performance-recheck
node scripts/benchmark-local-search.mjs --root "$baseline_root" --suite optimizations --output .local/performance-recheck/baseline.json
node scripts/benchmark-local-search.mjs --root "$candidate_root" --suite optimizations --output .local/performance-recheck/candidate.json
```

原始探针输出含本机环境数据，仅保存在私有目录；公开采样数据需移除硬件、主机平台、机器路径和完整 User-Agent。`--smoke` 仅用于小样本正确性检查，不作为性能证据。浏览器按[既有 fixture 构建说明](0.3.9.md#浏览器合成-fixture-的完整构建与运行)使用同一当前驱动构建双方，替换版本/marker 和来源目录，将 phase 设为 `optimizations`。也可分别运行 `optimization-content`、`optimization-snapshot`、`optimization-lua`、`optimization-tokens`。

本轮仅访问回环地址及合成数据库；版本和 marker 已核对，双方 fixture 都回报合成库删除成功。专用浏览器和回环服务已停止。未安装脚本、访问真实 Wiki 数据库、执行整包站点验收或测量输入到绘制时延；没有测量额外 ID 集合的堆占用。快照导入后的 MiniSearch 增量更新沿用原有引用行为，不把“正文整理不修改输入”扩大为“后续所有索引操作均深拷贝输入”的保证。

本记录与采样数据作为本轮新增证据，不覆盖 0.3.9 历史测量。
