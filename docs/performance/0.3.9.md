# 0.3.9 局部性能优化记录

测量日期：2026-10-03。基线为 **0.3.8 / `1431c1265b132f090f22508a803385b5f9bd7d67`**，候选主要缓存和查询实现的 Node / Chrome 配对采样点为 **0.3.9 / `44e7eebfb0e853b49e675a5158a75da9e9cab937`**。候选测量记录中的工作树标志为 dirty，测量工具和交付文档当时仍在整理。最终交付另有采样后的刷新与失败重建 generation 边界修复，最终生产源码因此与计时采样点有差别；这部分并发通知行为以最终正确性复验记录为准，未重新归入主要缓存/查询的配对耗时。

本次保留六种搜索模式、同步搜索接口、AND→OR 回退、排序、高亮坐标、旧快照格式、原生撤销和跨标签写锁，不新增依赖、设置、遥测、Worker 或数据库迁移。收益集中在打包范围、热查询、结果失效合并、增量准备与重复发布调度；首次长文查询和单次快照序列化仍有明显成本。

正文缓存同时受 **8 MiB 文本计费载荷**与 **128 条**上限约束，按 `normalizedText.length * 2` 计费。该值不含 Map、字符串对象或其他堆开销。超预算单篇仍计算完整摘要，且不清空已有缓存；原文直命中、空字符串命中、LRU 淘汰、更新/删除、并发重建重放与快照导入都有正确性断言。正文与标题缓存只存在于当前索引内存，不进入快照。

标题头数组不再长期持有正文对象，**不代表 IndexedDB 支持字段投影或完全没有读取正文**。bootstrap 游标和各 handle 的 `throughLocalSeq` 独立维护；文件推进全局序列时页面 replay 为 0，标题 handle 仍从 101 追到 102，页数维持 100，不重建 bootstrap 或发送页面结果通知。namespace 从轻量内存条目汇总，最后一页删除、namespace 移动/改名及同数量重定向更新均按事实变化处理。

显式发布的原有完整校验保留。配对存储探针中，“同序列再次显式 publish”前后都读取旧快照 1 次、返回 JSON 长度 16,611 字符，并返回 `not-newer`；本次消除的是残余自动工作，没有绕过候选序列冻结、generation、二次序列校验、SHA、大小/配额保护或 clear 后抑制回写。

相关测试位于 [Analyzer](../../tests/analyzer/analyzer.test.ts)、[正文](../../tests/search/content-search.test.ts)、[标题](../../tests/search/title-index.test.ts)、[索引生命周期](../../tests/search/index-lifecycle.test.ts)、[页面运行态](../../tests/runtime/page-search-runtime.test.ts)、[快照](../../tests/search/index-snapshot.test.ts) 和 [面板](../../tests/ui/search-panel.test.ts)。独立复核发现的“正文已更新但后续 Lua 失败时漏通知”和“显式发布等待队列期间新生成重试任务未被消费”已修复，并加入定向竞争测试；最终 Spec 复核无未关闭问题。
